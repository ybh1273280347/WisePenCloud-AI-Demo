当项目出现第三方日志、warning 或控制台噪音时，按以下规则处理。

一、先分类，不要直接过滤

先判断输出来源：

1. logging 日志：
   - 走 logging logger
   - 可以被 Loguru intercept 接管

2. Python warnings：
   - 形如 file.py:line: WarningCategory: message
   - 使用 warnings 模块控制
   - 不会自动走 logging intercept

3. stdout / stderr 直接输出：
   - print
   - C/C++ 扩展
   - 子进程输出
   - 不属于 logging 或 warnings

4. import 阶段 warning：
   - 可能发生在项目代码设置 filter 之前
   - 需要调整 import 顺序、启动方式，或使用依赖配置从源头解决

二、优先从源头解决

如果 warning 是依赖选择了 deprecated API，不要优先 filter。

例如：
- Uvicorn + websockets.legacy warning
- 应优先设置 uvicorn ws protocol：
  ws="websockets-sansio"
  或 ws="wsproto"

不要用 warnings.filterwarnings 硬压 websockets.legacy。

三、只有低价值第三方噪音才过滤

允许过滤：
- jieba 触发的 pkg_resources deprecated warning
- 明确来自第三方且短期无法修复的 warning

禁止过滤：
- 项目自身 warning
- 所有 DeprecationWarning
- 所有 UserWarning
- 真实运行时错误
- 会影响协议正确性的 stdout/stderr 输出

四、过滤必须精确

使用：
- message
- category
- 必要时 module

推荐结构：

SUPPRESSED_WARNING_FILTERS = (
    {
        "message": r".*pkg_resources is deprecated.*",
        "category": UserWarning,
    },
)

def setup_warning_filters() -> None:
    for item in SUPPRESSED_WARNING_FILTERS:
        warnings.filterwarnings(
            "ignore",
            message=item["message"],
            category=item["category"],
        )

不要写：
warnings.filterwarnings("ignore", category=DeprecationWarning)
warnings.filterwarnings("ignore", category=UserWarning)

五、注意设置时机

如果 warning 在 import uvicorn 时触发，则 filter 必须在 import uvicorn 前设置。

如果使用：
uvicorn chat.main:app

则 uvicorn 自身可能在导入 chat.main 前已经触发 warning。
这种情况下应使用：
- uvicorn CLI 参数，例如 --ws websockets-sansio
- 或 PYTHONWARNINGS
- 或改为 python -m chat.main 入口

六、logging intercept 只处理 logging

Loguru intercept 不能解决 warnings。
不要把 warnings 问题误判为 logging 配置问题。

七、stdout/stderr 协议通道必须单独处理

如果是 worker 子进程：
- stdout 是协议通道时，必须保持纯净
- stderr 用于日志
- 第三方库噪声必须重定向到 stderr
- 不要用 warning filter 解决协议污染

八、必须记录处理原因

每新增一条 SUPPRESSED_WARNING_FILTERS，都要写清楚：

1. 来源库
2. warning 内容
3. 为什么不能从源头解决
4. 后续什么时候可以移除

九、不要修改模型可见内容

不要因为日志清理修改：
- Tool Result
- Tool Error
- ToolContent Metadata
- 工具 schema description
- worker JSON 字段
- 模型可见 Markdown
