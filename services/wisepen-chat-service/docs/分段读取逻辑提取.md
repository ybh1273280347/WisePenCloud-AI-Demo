```python
        ...

    def get(self, content_id: str) -> Optional[StoredContent]:
        ...

    def delete(self, content_id: str) -> None:
        ...

        ...
```

# Step 7：normalize 与 offset 语义

这是本次迁移必须修复的问题。

旧代码中存在类似行为：

```python
text[chunk.start_offset:chunk.end_offset].strip()
```

这会导致：

* offset / next_offset 指向原始文本位置
* returned_length 是 strip 后文本长度
* text 与 offset 语义不一致

新实现要求：

## 7.1 normalize 只允许发生在写入阶段

put_content 中：

```python
if self._normalize_text:
    text = text.strip()
```

之后所有 offset、chunk.start_offset、chunk.end_offset 都必须基于存储后的 text。

## 7.2 read_window 不允许 strip slice

禁止：

```python
window_text = item.text[start:end].strip()
```

必须：

```python
window_text = item.text[start:end]
returned_length = len(window_text)
```

## 7.3 read_chunk_window 不允许 strip slice

同理：

```python
window_text = item.text[start_offset:end_offset]
returned_length = len(window_text)
```

## 7.4 formatter 不修改正文

formatter 只格式化，不 trim、不 normalize、不改 window.text。

* next_offset = chunks[end_chunk].end_offset if truncated else None
* metadata 中加入：

  * end_chunk_index

# Step 16：legacy content_id 处理策略

旧 content_id 格式：

```text

```


## 情况 A：没有发现强依赖

如果确认旧 content_id 没有持久化、没有外部 API 依赖、没有测试强依赖：

* 不做 legacy 兼容
* 直接使用新格式 cnt_<uuid_hex>
* read_tool_content_window 找不到旧 id 时保持原有 not found 文案
* 在最终输出中说明：旧 id 属于内存 TTL 内容，迁移后不保证可继续读取

## 情况 B：发现强依赖

如果发现有明确强依赖：

* 在 read_tool_content_window 中检测 legacy id
* 检测规则：

  * content_id 不以 "cnt_" 开头
  * 且包含 ":"
* 返回明确提示，避免与普通 expired 混淆：

```text
[Tool Result] Cached tool content uses a legacy content_id format and may have been created before the ContentStore migration. Please rerun the source tool to refresh the content.
```

不要为了兼容 legacy id 引入复杂双 store 迁移，除非项目里已经有旧 store 可访问。
