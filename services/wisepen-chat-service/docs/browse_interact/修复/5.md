继续 review：这次是 **`protocol.py`**。

整体判断：**这个文件主方向是对的，但还残留几个会影响 agent 行为的协议语义问题。**
它不是代码风格问题，而是 **错误协议会不会诱导模型乱重试、误解状态** 的问题。

# 总体评价

好的地方：

```text
1. PageState / SessionState / ToolError / ActionResult 这些协议模型是有意义的。
2. error response 已经收敛成嵌套 error 对象。
3. recommended_next_action 已经删掉。

6. build_success_response / build_error_response 边界清楚。
```

但现在主要问题是：

```text
1. 部分错误 message 和当前行为不一致。
2. INTERNAL_ERROR 默认 retryable=True 太危险。
3. recovery_hint 有些还是会诱导无意义重试。
4. user intervention 返回了过多检测细节。
5. profile/browser unavailable 错误有点重复，但还能接受。
```

# P0：`SNAPSHOT_REQUIRED` 文案已经过时

当前逻辑里，ref action 已经允许省略 `snapshot_id`，只要 `SnapshotManager` 有当前有效 snapshot，就会自动使用。

但错误文案还是：

```text
A current snapshot_id is required for ref-based actions.
```

这会误导模型，以为“必须传 snapshot_id”。实际上现在真正缺的是：

```text
当前没有有效 snapshot
```

应该改成：

```python
message="A current snapshot is required before using refs."
```

`reason` 也要改。现在写的是：

```text
A fresh snapshot is required before click_ref or fill_ref.
```

但现在 ref-based action 已经包括：

```text
click_ref
fill_ref
select_ref
check_ref
```

建议改成：

```python
reason="Take a fresh snapshot before using ref-based actions."
```

这个是 P0，因为你刚刚遇到的循环失败，很大一部分就是协议文案和真实行为不一致。

# P0：`make_internal_error()` 不应该默认 `retryable=True`

当前：

```python
def make_internal_error(...):
    return ToolError(
        category=ErrorCategory.INTERNAL.value,
        code=ToolErrorCode.INTERNAL_ERROR.value,
        ...
        retryable=True,
        recovery_hint=RecoveryHint(
            type="inspect_status",
            required_before_retry=False,
            ...
        ),
    )
```

这个很危险。

`INTERNAL_ERROR` 对 agent 来说通常不可恢复。它不知道内部哪里坏了，只会：

```text
status -> retry -> status -> retry
```

容易形成无意义循环。

建议：

```python
retryable=False
```

如果某个内部错误确实可恢复，那应该不要走 `INTERNAL_ERROR`，而是走更具体的：

```text
BROWSER_UNAVAILABLE
SESSION_EXPIRED
ACTION_FAILED
```

所以这里建议改成：

```python
def make_internal_error(..., retryable: bool = False):
    ...
```

默认不可重试。

# P1：`make_action_failed_error()` 的 recovery_hint 有点泛

当前所有 action failed 都返回：

```text
inspect_page_state
```

这比以前的 recommended_next_action 好，但还是偏虚。

对 agent 有用的信息其实是：

```text
当前 action 失败了
页面仍然可用
是否要 retry 由 agent 自己判断
```

现在的 hint 可以保留，但 `reason` 建议更短，不要带“refresh snapshot or change strategy”这种半建议式语气。

建议：

```python
RecoveryHint(
    type="inspect_page_state",
    required_before_retry=False,
    reason="The page may still be usable. Inspect current state before retrying."
)
```

这样更符合“工具只报告状态，不教 agent 做任务”。

---

# P1：`make_ref_not_found_error()` 的 retryable 语义需要谨慎

当前：

```python
retryable=True
recovery_hint.required_before_retry=False
```

这会让模型觉得“可以直接重试”。但如果 ref 找不到，通常有两种情况：

```text
1. DOM 变化了，需要重新 snapshot。
2. 模型选错 ref，需要换 ref。
```

直接重试同一个 ref 没意义。

建议：

```python
retryable=True
recovery_hint.required_before_retry=True
recovery_hint.type="refresh_snapshot"
```

或者更保守：

```python
retryable=False
```

我倾向于第一种：**ref not found 大概率需要刷新 snapshot**。

# P1：`make_user_intervention_error_from_signal()` 返回了太多 detector 细节

当前 context 里返回：

```python
{
    "detected_reason": signal.type,
    "confidence": signal.confidence,
    "evidence": signal.evidence,
}
```

`confidence` 和 `evidence` 对 agent 任务恢复帮助不大，反而像调试字段。尤其 `evidence` 很容易逐渐塞进 DOM 片段、关键词、selector、内部检测结果。

建议 agent-facing 只保留：

```python
context={
    "detected_reason": signal.type
}
```

内部日志可以记录：

```text
confidence
evidence
```

但不要放进 tool output。

这符合之前定的规范：**调试信息进日志，不进 agent-facing response。**

# P1：`make_user_intervention_error()` 和 `make_user_intervention_error_from_signal()` 重复

现在同时存在：

```python
make_user_intervention_error(...)
make_user_intervention_error_from_signal(signal)
```

如果项目里实际只用后者，前者就是冗余 API。

这不是功能 bug，但它会让协议层 API 变宽。

# P2：`error_to_dict()` 会把 None reason 输出出去

`asdict(error.recovery_hint)` 会包含：

```json
{
  "reason": null
}
```

如果 `reason` 是 None，会出现无意义字段。

目前大多数 reason 都有值，所以不是大问题。
如果你想更干净，可以写个小函数过滤 None：

```python
def drop_none(data: Dict[str, Any]) -> Dict[str, Any]:
    return {k: v for k, v in data.items() if v is not None}
```

然后：

```python
payload["recovery_hint"] = drop_none(asdict(error.recovery_hint))
```

但这个不是必须。

# P2：`get_page_state()` 把所有异常都当作 closed

当前：

```python
except Exception:
    return PageState(url="", title="", ready_state=None, is_closed=True)
```

这个策略简单，但有一点语义风险：
如果只是 `page.title()` 或 `document.readyState` 偶发失败，它会把页面标成 closed。

更稳的做法：

```python
except Exception:
    return PageState(
        url=getattr(page, "url", ""),
        title="",
        ready_state=None,
        is_closed=page.is_closed() if page else True,
    )
```

这样不会因为一次 evaluate 失败就伪装成页面关闭。

不是 P0，但后面遇到状态误判时要改。
