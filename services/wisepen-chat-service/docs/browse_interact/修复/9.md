# 2. status.py

## 2.1 当前判断

`status.py` 当前逻辑基本正确。

它的职责是：

```text
读取当前 session/page 状态。
不创建 session。
不导航。
不改变页面。
不 invalidate snapshot。
不触发 intervention detection。
```

当前实现中，`status` 在传入 `browser_session_id` 时会校验 session；未传时直接返回当前 manager 状态。这是合理的。状态返回里包含 `has_session` 和 `is_session_alive`，这是 status action 的业务结果，不属于调试字段。

## 2.2 本轮不修改

保持现状。

验收标准：

```text
1. status 不调用 get_existing_page_or_error。

5. status 成功响应仍包含 has_session / is_session_alive。
```

# 3. control.py

当前 `control.py` 包含 `scroll / key / wait`。其中 `key` 的组合键释放逻辑存在真实风险：如果中途异常，已经按下的 modifier 可能不会被释放。当前实现是先依次 `keyboard.down()`，再依次 `keyboard.up()`。

## 3.1 修复 key 组合键释放

### 当前问题

当前组合键逻辑类似：

```python
for key in keys:
    await page.keyboard.down(key)
for key in reversed(keys):
    await page.keyboard.up(key)
```

如果 `down(Control)` 成功，`down(X)` 失败，`Control` 可能保持按下状态。

### 修改目标

使用 `try/finally` 保证已经按下的键一定释放。

### 推荐实现

```python
pressed = []

try:
    if len(keys) == 1:
        await page.keyboard.press(keys[0])
    else:
        for key in keys:
            await page.keyboard.down(key)
            pressed.append(key)

        for key in reversed(pressed):
            await page.keyboard.up(key)

    await page.wait_for_timeout(SETTLE_WAIT_MS)

except Exception as error:
    for key in reversed(pressed):
        try:
            await page.keyboard.up(key)
        except Exception:
            pass

    log_fail("浏览器按键", str(error))
    page_state = await get_page_state(page)
    return build_error_response(
        session_state=session_state(session_manager),
        page_state=page_state,
        error=make_action_failed_error(
            action_type="key",
            message="Key action failed.",
            diagnostic_code="KEY_FAILED",
        ),
    )
```

注意：

```text
1. 原始异常只进 log_fail。
2. agent-facing message 不拼接原始异常。
3. key 成功后仍然 invalidate snapshot。
4. key 失败时不额外 invalidate snapshot。
```

---

## 3.2 修复 control action 错误 message

当前 `scroll / key / wait` 的错误 message 会拼接原始异常，例如 `Scroll failed: {error}`、`Key action failed: {error}`、`Wait failed: {error}`。

```python

message="Key action failed."

```

```python
log_fail("浏览器按键", str(error))
log_fail("浏览器等待", str(error))
```

```text
4. wait 后继续执行 intervention detection。
```

# 4. navigation.py

当前 `navigation.py` 包含 `navigate / go_back / go_forward`。现在的问题是：只有导航成功后才 invalidate snapshot；但 `page.goto()`、`go_back()`、`go_forward()` 即使失败或 timeout，也可能已经改变了 DOM 或页面 URL。当前实现中 `snapshot_manager.invalidate()` 在成功路径之后。

## 4.1 导航开始前 invalidate snapshot

### 当前问题

失败导航可能造成页面部分变化，但旧 snapshot 仍被认为有效。

### 修改目标

只要即将执行页面级导航，就先 invalidate snapshot。

### 修改 `handle_navigate`

从：

```python
try:
    await page.goto(...)
    await page.wait_for_timeout(...)
except Exception:
    ...
snapshot_manager.invalidate()
```

改为：

```python
snapshot_manager.invalidate()

try:
    await page.goto(url, wait_until=wait_until, timeout=NAVIGATION_TIMEOUT_MS)
    await page.wait_for_timeout(SETTLE_WAIT_MS)
except Exception as error:
    ...
```

### 修改 `handle_navigation_direction`

从：

```python
try:
    if act_type == "go_back":
        await page.go_back()
    else:
        await page.go_forward()
    await page.wait_for_timeout(...)
except Exception:
    ...
snapshot_manager.invalidate()
```

改为：

```python
snapshot_manager.invalidate()

try:
    if act_type == "go_back":
        await page.go_back()
    else:
        await page.go_forward()

    await page.wait_for_timeout(SETTLE_WAIT_MS)
except Exception as error:
    ...
```

---

# 5. observation.py

当前 `observation.py` 包含 `snapshot / screenshot / get_content`。主要问题集中在 `get_content` 的 rendered extraction 脚本：它过滤太激进，会删除 `form / input / button / select / textarea`，还会根据 id/class 中的 `header/nav/footer/banner/modal/promo` 等词删除节点。

这会让 `get_content` 在登录页、表单页、权限页、验证码页、短提示页上丢失关键内容。

---

## 5.1 收敛 get_content 过滤规则

### 当前问题

当前 `removeSelectors` 包含：

```javascript
'nav',
'footer',
'header',
'aside',
'form',
'button',
'select',
'textarea',
'input',
```

还有：

```javascript
const noisyPattern = /(cookie|banner|advert|ads|promo|modal|popup|sidebar|nav|footer|header)/i;
```

这些规则会误删真实页面状态。

### 修改目标

`get_content` 是读取当前浏览器页面状态，不是强正文抽取。
宁愿多返回一点噪音，也不能删掉登录、表单、权限、验证相关内容。

### 推荐修改

把 `removeSelectors` 改为：

```javascript
const removeSelectors = [
    'script',
    'style',
    'noscript',
    'template',
    'svg',
    'canvas',
    'iframe',
    '[hidden]',
    '[aria-hidden="true"]'
];
```

删除整段 `noisyPattern` 逻辑：

```javascript
const noisyPattern = ...;

clone.querySelectorAll('*').forEach(node => {
    const id = node.getAttribute('id') || '';
    const cls = node.getAttribute('class') || '';

    if (noisyPattern.test(id) || noisyPattern.test(cls)) {
        node.remove();
    }
});
```

`cloneAndClean` 最终应接近：

```javascript
function cloneAndClean(element) {
    const clone = element.cloneNode(true);

    for (const selector of removeSelectors) {
        clone.querySelectorAll(selector).forEach(node => node.remove());
    }

    return clone;
}
```

## 5.2 observation action 失败改成 ACTION_FAILED

当前 `snapshot / screenshot / get_content` 失败时使用：

```python
make_internal_error(...)
```

并且 message 拼接了原始异常。

这些失败属于 action 执行失败，不应默认视为 internal error。改用：

```python
make_action_failed_error(...)
```

需要同步 import：

```python
from ..protocol import (
    ...
    make_action_failed_error,
)
```

### snapshot 失败

改为：

```python
error=make_action_failed_error(
    action_type="snapshot",
    message="Snapshot failed.",
    diagnostic_code="SNAPSHOT_FAILED",
)
```

### screenshot 失败

改为：

```python
error=make_action_failed_error(
    action_type="screenshot",
    message="Screenshot failed.",
    diagnostic_code="SCREENSHOT_FAILED",
)
```

### get_content fallback 失败

改为：

```python
error=make_action_failed_error(
    action_type="get_content",
    message="Get content failed.",
    diagnostic_code="GET_CONTENT_FAILED",
)
```

原始异常仍然只写日志：

```python
log_fail("浏览器快照", str(error))
log_fail("浏览器截图", str(error))
log_fail("页面内容备用提取失败", str(error))
```
