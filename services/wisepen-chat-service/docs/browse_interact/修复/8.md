继续 review：这个是 **`actions/observation.py`**，包含 `snapshot / screenshot / get_content`。整体方向不错，尤其 `get_content` 已经从 `page.content() -> ContentProcessor` 主路径改成 rendered text 主路径了。但这里有几个会影响实际任务质量的问题。

---

# 1. P0：`get_content` 的噪音过滤会误删正文

当前：

```javascript
const noisyPattern = /(cookie|banner|advert|ads|promo|modal|popup|sidebar|nav|footer|header)/i;
...
if (noisyPattern.test(id) || noisyPattern.test(cls)) {
    node.remove();
}
```

这太激进。很多正文容器 class 可能包含：

```text
header
nav
banner
modal
```

比如文章里的 `header-image`、`modal-content`、`promo-section` 可能并不一定是垃圾。尤其你是在候选主内容区域里递归删节点，这会导致 **正文被误删**。

建议第一版只删明确结构标签：

```text
script/style/noscript/template/svg/canvas/iframe
```

`nav/footer/header/aside/form/button/input/select/textarea` 可以保留，或者只在 `document.body` fallback 时弱过滤。
`noisyPattern` 建议先删掉，至少不要匹配 `header/nav/footer` 这种高误伤词。

---

# 2. P0：`removeSelectors` 里删掉 `form/input/button`，会让 get_content 看不到关键页面状态

你之前说 `get_content` 要弥补 fetch 无法使用用户权限的问题。这意味着它经常用于：

```text
登录页
权限页
搜索结果页
表单校验页
验证码页
```

但现在脚本会移除：

```javascript
'form',
'button',
'select',
'textarea',
'input'
```

这会导致登录页、表单页、错误提示页的信息残缺。比如：

```text
Sign in
Username
Password
Submit
Incorrect username or password
```

其中一部分可能在 form 内，直接被删掉。
建议不要移除 `form/input/button/select/textarea`。`get_content` 不是正文抽取器，它是“当前页面可读状态读取器”。

可改为：

```javascript
const removeSelectors = [
  'script',
  'style',
  'noscript',
  'template',
  'svg',
  'canvas',
  'iframe',
  '[hidden]',
  '[aria-hidden="true"]'
];
```

导航噪音宁愿留一点，也不要把状态信息删没。

# 3. P1：`handle_snapshot` 对 mode 做了重复 schema 检查，但可以接受

当前：

```python
mode = action.get("mode", "full")
if mode not in ("full", "focused"):
    return build_error_response(...)
```

按你们规范，tool schema 已约束参数，内部不需要过度防御。但这里是 action 边界，而且 `snapshot_manager.take()` 里也应该拒绝非法 mode。

建议：

```text
保留也行，但最好把非法 mode 的最终兜底放在 snapshot_manager.take。
handler 这里只做 action 编排。
```

不是硬伤。

# 4. P1：`snapshot` 失败返回 `make_internal_error`，但应该更像 `ACTION_FAILED`

当前：

```python
error=make_internal_error(
    message=f"快照失败: {error}",
    diagnostic_code="SNAPSHOT_FAILED",
)
```

snapshot 脚本失败、页面 evaluate 失败，不一定是 internal error。对 agent 来说它是一次 action failed。更合适：

```python
make_action_failed_error(
    action_type="snapshot",
    message="Snapshot failed.",
    diagnostic_code="SNAPSHOT_FAILED",
)
```

并且不要把原始异常拼到 message 里。原始异常进日志就行。
`screenshot/get_content` 同理，`SCREENSHOT_FAILED / GET_CONTENT_FAILED` 更像 action failed，不是内部错误。

---

# 5. P1：`screenshot` base64 可能太大

当前截图：

```python
page.screenshot(type="jpeg", quality=40, scale="css")
```

质量 40 是对的，但仍然可能返回很大的 base64。这个不一定马上改，因为接口已经如此。

建议后续考虑：

```text
full_page=False 明确写出来
限制 viewport
或者 screenshot 只给视觉调试用，不参与常规 agent 任务
```

当前 Playwright 默认不是 full page，所以问题不大。可选改：

```python
full_page=False
```

让语义明确。

# 6. P1：`get_content` fallback 到 `ContentProcessor` 可能把重要短文本过滤掉

你现在主路径失败或空才 fallback：

```python
html = await page.content()
cleaned = processor.process(html)
content = cleaned if cleaned else ""
```

这没问题。但注意 fallback 会走 `ContentProcessor` 的最小长度、反爬过滤。由于只是 fallback，可以接受。

不过如果 rendered content 因脚本 bug 返回空，登录页/短提示页 fallback 也可能空。
所以主路径必须尽量不因为过滤过度而返回空。也就是前面 P0：别删 `form/input/button`，别用 `noisyPattern` 激进删。

# 7. P2：`normalize_rendered_text` 和 JS `cleanText` 重复

JS 已经做了一次：

```javascript
cleanText(...)
```

Python 又做：

```python
normalize_rendered_text(...)
```

这不是问题，跨边界后再轻量 normalize 一次可以接受。
但如果你想简洁，保留 Python 端就够，JS 端也可以只返回原始 `innerText`。不是必须。

---

# 8. P2：`processor` 在 snapshot/screenshot 中没用

这是统一 handler 签名导致的，不用处理。

# 建议修改清单

## 必改

```text
1. get_content 的 RENDERED_CONTENT_SCRIPT 不要移除 form/input/button/select/textarea。
2. 删除或大幅收敛 noisyPattern，不要按 class/id 里出现 header/nav/banner 就删节点。
```

## 建议改

```text
3. snapshot/screenshot/get_content 的失败错误从 make_internal_error 改成 make_action_failed_error。
4. 错误 message 不拼原始异常，原始异常只进 log_fail。
5. screenshot 明确 full_page=False。
```
