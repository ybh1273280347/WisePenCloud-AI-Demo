这个 `controller.py` 整体比前几个文件干净，职责也比较清楚：

```text
controller.py = action 分发 + 串行执行 + manager 组装
```

主方向没问题。现在主要看 **运行时兜底、生命周期、死参数** 这几个点。

---

# 1. P0：缺少 controller 级别的异常兜底

现在最后是直接：

```python
return await handler(...)
```

如果某个 handler 内部漏掉异常，比如 snapshot 脚本解析、Playwright 调用、某个 None 访问，异常会直接抛出到上层，可能破坏 SSE / tool call 协议。

虽然 handler 内部已经 catch 了很多，但 controller 应该是最后一道边界。

建议改成：

```python
try:
    return await handler(
        self._session_manager,
        self._snapshot_manager,
        self._intervention,
        self._processor,
        browser_session_id,
        action,
    )
except Exception as error:
    log_error(
        "browse_interact 执行异常",
        str(error),
        action_type=act_type,
    )
    return build_error_response(
        session_state=get_session_state(
            self._session_manager.session_id,
            valid=self._session_manager.is_session_alive,
        ),
        page_state=await get_page_state(self._session_manager.page),
        error=make_internal_error(
            message="Browse interaction failed unexpectedly.",
            diagnostic_code="UNHANDLED_CONTROLLER_ERROR",
        ),
    )
```

注意：**原始异常只进日志，不进 tool output。**

这条我认为是 P0。controller 是协议边界，不应该让内部 Python 异常直接炸出去。

---

# 2. P0：controller 没有暴露 cleanup

现在 `BrowserInteractController` 创建了：

```python
self._session_manager = BrowserSessionManager(...)
```

但没有：

```python
async def cleanup(self) -> None:
    await self._session_manager.cleanup()
```

如果 session manager 里补了 `cleanup/close`，controller 也必须向外暴露，否则 tool / app 层没法释放浏览器。

建议加：

```python
async def cleanup(self) -> None:
    await self._session_manager.cleanup()
```

或者：

```python
async def close(self) -> None:
    await self._session_manager.close()
```

名字二选一，项目里统一就行。

---

# 3. P1：`persist_profile` 仍然是死参数链路

controller 里还收：

```python
persist_profile: bool = False
```

然后传给：

```python
BrowserSessionManager(..., persist_profile=persist_profile)
```

但如果 `session.py` 里这个参数没有真实作用，那 controller 这里也应该删。

当前状态是：

```text
controller 收 persist_profile
session 收 persist_profile
但行为层没有使用
```

这就是典型“配置旋钮存在，但没有语义”。

建议：

```text
如果 session.py 删除 persist_profile，controller.py 同步删除。
如果保留，就必须明确它到底影响哪个行为。
```

按当前架构，我倾向于删除。

---

# 4. P1：`ActionHandler = Callable[..., Awaitable[str]]` 太松

现在：

```python
ActionHandler = Callable[..., Awaitable[str]]
```

这会隐藏 handler 签名错误。你所有 handler 实际上都是统一签名：

```python
(
    session_manager,
    snapshot_manager,
    intervention,
    processor,
    browser_session_id,
    action,
) -> str
```

可以改成更具体的类型：

```python
ActionHandler = Callable[
    [
        BrowserSessionManager,
        SnapshotManager,
        UserInterventionDetector,
        ContentProcessor,
        Optional[str],
        Dict[str, Any],
    ],
    Awaitable[str],
]
```

这不是必须，但能防止以后某个 handler 少一个参数，静态上完全看不出来。

# 5. P1：`action` 边界可以稍微更明确

现在：

```python
action = request.get("action")

if action is None:
    return await self._no_action()

act_type = action.get("type")
```

如果 `action` 不是 dict，会直接炸。
理论上 schema 会保证它是 object，所以这不是大问题。

但 controller 是最外层协议入口，保留一个边界检查也合理：

```python
if action is None:
    return await self._no_action()

if not isinstance(action, dict):
    return await self._invalid_schema("Action must be an object.")
```

这个检查不是无意义防御，因为它发生在外部协议入口，不是内部链路。

但如果你坚持完全信任 schema，这条可以不加。P1，不是硬伤。

---

# 6. P1：`browser_session_id == ""` 归一化应该保留，但 session 层也要做

这里：

```python
if raw_browser_session_id == "":
    browser_session_id = None
elif raw_browser_session_id is None:
    browser_session_id = None
else:
    browser_session_id = raw_browser_session_id
```

这个是合理的。因为你们的调用日志里确实存在：

```json
"browser_session_id": ""
```

建议写得更短：

```python
browser_session_id = request.get("browser_session_id") or None
```

不过这会把其他 falsy 值也变 None。schema 下只有 string/null，问题不大。

但更重要的是：**session.py 也应该兜底处理空字符串**。controller 做一次，session 层再做一次，不算坏，因为这是你们实际协议历史造成的。

---

# 7. P2：`context` 完全没用

现在：

```python
async def execute(
    self,
    request: Dict[str, Any],
    context: Optional[Dict[str, Any]] = None,
) -> str:
```

然后传给：

```python
_execute_inner(request=request, context=context)
```

但 `_execute_inner` 里也没用。

如果 tool adapter 接口要求必须有 `context`，保留没问题。
如果没有要求，可以删除 `_execute_inner` 的 `context` 参数，只保留 `execute` 接口。

当前不是问题，只是噪音。

---

# 8. P2：`ACTION_HANDLERS` 和 schema 需要测试保证一致

这里 map 本身没问题：

```python
ACTION_HANDLERS = {
    "status": handle_status,
    "navigate": handle_navigate,
    ...
}
```

但它必须和 tool schema 里的 action enum 保持一致。

不要在运行时代码里加复杂校验，建议在测试里做：

```text
schema action enum == ACTION_HANDLERS.keys()
```

否则以后新增 action，容易只改一边。

# 建议修改清单

## 必改


## 建议改

```text

```
