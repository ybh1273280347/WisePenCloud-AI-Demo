# 1. P0：没有 `cleanup()`，资源会泄漏

当前 `BrowserSessionManager` 只有创建和校验，没有看到公开的：

```python
async def cleanup(self) -> None:
    ...
```

也没有内部 `_cleanup()`。

这意味着如果 controller / tool 生命周期结束，可能没法主动关闭：

```text
BrowserContext
Playwright
Page
```

早期版本里是有 `cleanup -> _cleanup` 的，且会依次关闭 page、context、playwright。现在这版缺失了。当前文件确实只维护 `_playwright / _context / _page / _session_id`，但没有释放路径。

必须补：

```python
async def cleanup(self) -> None:
    await self.close()

async def close(self) -> None:
    ...
```

关闭顺序建议：

```text
page.close()
context.close()
playwright.stop()
```

并且最后清空：

```python
self._page = None
self._context = None
self._playwright = None
self._session_id = None
```

---

# 2. P0：启动失败后没有 stop playwright

当前启动流程是：

```python
if self._playwright is None:
    self._playwright = await async_playwright().start()

...
self._context = await self._playwright.chromium.launch_persistent_context(...)
```

如果 `launch_persistent_context()` 抛异常，代码会进入 `except`，记录日志并 raise `BrowserSessionError`，但没有：

```python
await self._playwright.stop()
self._playwright = None
```

这会造成 **Playwright driver 泄漏**。当前异常处理只分类和打日志，没有释放已经启动的 `_playwright`。

修法：

```python
except Exception as exc:
    diagnostic_code = self._classify_launch_error(exc)

    try:
        if self._context is not None:
            await self._context.close()
    except Exception:
        ...

    try:
        if self._playwright is not None:
            await self._playwright.stop()
    except Exception:
        ...

    self._context = None
    self._page = None
    self._playwright = None
    self._session_id = None

    ...
```

# 3. P0：`launch_persistent_context()` 的无 `user_data_dir` 分支有问题

当前代码：

```python
if self._automation_user_data_dir:
    self._context = await self._playwright.chromium.launch_persistent_context(
        user_data_dir=str(self._automation_user_data_dir),
        **launch_kwargs
    )
else:
    self._context = await self._playwright.chromium.launch_persistent_context(
        **launch_kwargs
    )
```

这个 `else` 分支非常可疑。`launch_persistent_context` 的核心语义就是用 `user_data_dir` 启动持久化上下文；你们架构里也一直强调 automation profile。Playwright 官方也把 browser context 视为隔离的浏览器 profile，而 persistent context 就应该有明确 profile 目录；否则这个分支不是“非持久化”，而是 API 语义错位。Playwright 文档也强调 context 是隔离 profile，而你们的目标本来就是 dedicated automation profile。([Playwright][1])

建议直接删掉 `else` 分支：

```python
if self._automation_user_data_dir is None:
    raise BrowserSessionError(
        "automation_user_data_dir is required.",
        diagnostic_code="PROFILE_UNAVAILABLE",
    )

self._context = await self._playwright.chromium.launch_persistent_context(
    user_data_dir=str(self._automation_user_data_dir),
    **launch_kwargs,
)
```

或者在 `__init__` 之前由 profile resolver 保证传入。**不要保留无 profile 的 persistent context 分支。**

# 4. P0：`browser_session_id=""` 会被当成有效 session id

你们日志里大量调用是：

```json
"browser_session_id": ""
```

但当前逻辑是：

```python
if browser_session_id is not None:
    error_code = await self.validate_session(browser_session_id)
```

空字符串不是 `None`，所以第一次 navigate 如果传 `""`，会走 validate，然后因为 `_session_id is None` 返回 `SESSION_NOT_FOUND`，而不是创建新 session。当前 `get_or_create_page()` 就是这么写的。

如果上层已经把 `""` 归一化成 `None`，那没事；如果没有，这就是 P0。

建议在 session 层兜底也做一次最小归一化：

```python
def normalize_session_id(browser_session_id: Optional[str]) -> Optional[str]:
    return browser_session_id or None
```

然后 `validate_session / get_existing_page / get_or_create_page` 开头都用：

```python
browser_session_id = browser_session_id or None
```

这不是“宽容参数类型转换”，这是兼容前端/调用层历史上用空字符串表示无 session 的协议现实。

# 5. P1：`persist_profile` 是死参数

构造函数有：

```python
persist_profile: bool = False
```

并保存了：

```python
self._persist_profile = persist_profile
```

但当前文件里完全没有使用它。

如果 profile resolver 已经在外面处理好了，那 `session.py` 不应该继续收这个参数。
如果 session.py 还负责 profile 解析，那它应该传给 resolver。

现在状态是：

```text
参数存在
字段存在
行为不存在
```

这违反你刚定的规范：不要保留无意义配置旋钮。

建议二选一：

```text
A. 删除 persist_profile 参数。
B. 引入 profile resolver，并真正使用 persist_profile。
```

以当前架构看，推荐 A：`session.py` 只接受最终的 `automation_user_data_dir`。

# 6. P1：`SESSION_ID_LENGTH` 命名不准

当前：

```python
SESSION_ID_LENGTH = 12
self._session_id = secrets.token_hex(SESSION_ID_LENGTH)
```

`secrets.token_hex(12)` 生成的是 **24 个 hex 字符**，不是 12 个字符。

改成：

```python
SESSION_ID_BYTES = 12
self._session_id = secrets.token_hex(SESSION_ID_BYTES)
```

或者：

```python
SESSION_ID_LENGTH = 24
self._session_id = secrets.token_hex(SESSION_ID_LENGTH // 2)
```

推荐前者。

# 7. P1：`get_or_create_page` 并发存在小问题

当前锁只包住创建分支：

```python
if browser_session_id is not None:
    ...
    return self._page, None

async with self._lock:
    ...
```

单用户本地场景问题不大。
但如果两个 `navigate` 几乎同时传 `browser_session_id=None`，第一个创建，第二个进入锁后会复用 page，这符合单 session 逻辑。

更大的问题是：如果已有 session，但 page closed，第二个 navigate 不带 id 可以重新创建；这也合理。

所以并发这里不是 P0，只是建议创建失败后必须清理状态。

# 8. P1：`validate_session` 的 alive 检测偏弱

当前：

```python
return self._page is not None and not self._page.is_closed()
```

这能检测 page close，但不能检测 browser/context 已经崩掉而 page 对象还没标 closed 的情况。

以前我们遇到过浏览器 runtime 问题，所以可以考虑在 `validate_session()` 中做轻量 probe：

```python
try:
    await self._page.evaluate("() => 1")
except Exception:
    return ToolErrorCode.SESSION_EXPIRED
```

但这个会让每个 action 多一次 roundtrip。我的建议：

```text
先不改。
如果后面出现“page 未关闭但操作全失败”，再加 async probe。
```

# 9. P2：类型标注不够准确

当前：

```python
async def get_or_create_page(...) -> Tuple[Page, Optional[ToolErrorCode]]:
```

但函数里会返回：

```python
return None, error_code
```

所以类型应该是：

```python
Tuple[Optional[Page], Optional[ToolErrorCode]]
```

这个不是运行时 bug，但影响静态阅读。

---

# 10. P2：`BrowserSessionError` 可以接受，但上层不能直出 message

这个类不是 pass-only，保留没问题：

```python
class BrowserSessionError(Exception):
    def __init__(self, message: str, diagnostic_code: str = "BROWSER_SESSION_ERROR") -> None:
        ...
```

它承载 `diagnostic_code`，有跨层价值。

但注意：它的 `message` 现在可能包含原始 Playwright 异常和本地路径。上层只能用它打日志，返回给 agent 时应该仍然是：

```text
Browser runtime is unavailable.
diagnostic_code=...
```

不要把 `Failed to create browser session: ...` 原样塞到 tool output。
