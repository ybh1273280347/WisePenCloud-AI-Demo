继续 review：这个文件是 **`action_runtime.py`**，它现在承担的是：

```text
action handler 共用运行时支撑：
- 构造 session_state
- 构造通用 error response
- 获取已有 page
- 获取或创建 page
- ref selector 校验
- browser/session 错误映射
```

整体定位是合理的，不是以前那种 `common.py` 垃圾桶。它确实服务 action runtime。当前代码见这个文件。

# 1. 最大问题：模块级 `_browser_error_from_*` 又回来了

现在有：

```python
def _browser_error_from_diagnostic(...)
def _browser_error_from_code(...)
```

这违反你已经定下来的规范：

```text
模块级不要用 _xxx。
模块导出边界由 __all__ 控制。
```

这两个函数不在 `__all__` 里，本来就已经是内部实现，不需要下划线。

建议改成：

```python
def browser_error_from_diagnostic(...)
def browser_error_from_code(...)
```

不导出即可。

这不是功能 bug，但你刚把全项目风格收敛完，不能让旧风格又混回来。

---

# 2. `get_or_create_page_or_error` 丢失 session 错误上下文

这里：

```python
if error_code is not None:
    return None, build_error_response(
        session_state=session_state(session_manager),
        page_state=await get_page_state(session_manager.page),
        error=_browser_error_from_code(error_code),
    )
```

而 `_browser_error_from_code()` 最后是：

```python
return make_session_error(error_code)
```

问题是：`SESSION_MISMATCH` / `SESSION_REQUIRED` 这类错误最好带上当前 session id。

`get_existing_page_or_error()` 做对了：

```python
make_session_error(error_code, session_manager.session_id)
```

但 `get_or_create_page_or_error()` 没传。

建议改：

```python
error=browser_error_from_code(error_code, session_manager.session_id)
```

然后：

```python
def browser_error_from_code(
    error_code: ToolErrorCode,
    current_session_id: Optional[str],
) -> ToolError:
    ...
    return make_session_error(error_code, current_session_id)
```

否则 agent 收到 session mismatch 时，恢复当前 session 的信息会变弱。

# 3. `selector_or_error_response` 类型太松

现在：

```python
async def selector_or_error_response(
    session_manager: BrowserSessionManager,
    page,
    ref: str,
):
```

建议补全：

```python
async def selector_or_error_response(
    session_manager: BrowserSessionManager,
    page: Page,
    ref: str,
) -> Tuple[Optional[str], Optional[str]]:
```

这不是啰嗦类型洁癖。这个函数是 action 层通用边界，返回 `(selector, error_response)`，签名明确能减少后面误用。

# 4. `get_or_create_page_or_error` 返回信息太少

现在它返回：

```python
Tuple[Optional[Page], Optional[str]]
```

但是创建 page 的时候，调用方其实很关心：

```text
created
reused
```

而现在这个信息丢了，只能靠外层猜。

你现在 response 里有：

```json
"session": {
  "created": false,
  "reused": true
}
```

但从这个 wrapper 的返回值看，handler 没法严谨知道本次到底是创建了新 session，还是复用了旧 session。

更稳的设计是让 session 层或 runtime 层返回一个小结果：

```python
@dataclass(frozen=True)
class PageResult:
    page: Page
    created: bool
    reused: bool
```

不过这会引入一个模型。按照你现在“克制”的风格，也可以先不加 dataclass，直接返回三元组：

```python
Tuple[Optional[Page], Optional[str], bool, bool]
```

但三元组会变丑。

我的建议：这个不是 P0，先记为 P1。当前最重要的是功能跑稳。

# 5. 浏览器错误映射可以保留

这里：

```python
NO_DISPLAY_SERVER
BROWSER_CRASHED_ON_START
LAUNCH_TIMEOUT
```

没有变成新的 `ToolErrorCode`，而是作为 `diagnostic_code` 映射到 `BROWSER_UNAVAILABLE`，这是对的。

也就是说：

```text
agent-facing code 保持粗粒度；
diagnostic_code 保留运维细节。
```

这符合我们之前收敛错误码的方向。

# 6. `get_existing_page_or_error` 设计没问题

这段：

```python
page, error_code = await session_manager.get_existing_page(browser_session_id)

if error_code is None:
    return page, None

return None, build_error_response(...)
```

这个 wrapper 很清楚。
