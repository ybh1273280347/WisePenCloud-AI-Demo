# 第一轮解耦后排查文档

## 0. 排查目标

本轮只做排查，不做大规模修复。

目标是确认第一轮解耦之后：

```text
1. web_fetch 没有残留文档解析 / OCR / Docling 职责。
2. document_parse 没有反向依赖 web_fetch。
3. PDF 没有误走 Docling / MarkItDown / 旧 DocumentParser。
4. Office 没有误走 OCR。
5. HTML / TXT / MD / CSV / JSON / XML / 图片没有误进 document_parse。
6. ToolContentStore、URL 安全策略、fetch fallback 链路没有被误改。
7. 文件直链的二进制流没有在 web_fetch 中被当作 HTML 处理或被静默丢弃。
```

最终边界以当前架构文档为准：Web Fetch 负责网络请求、Content-Type、HTML 正文提取、文件直链下载；文档解析工具接受文件路径或二进制流，并按后缀路由。

# 4. P0 排查项：文件直链二进制流有没有被正确分流

这是本轮最容易出小问题的地方。

架构文档规定：Web Fetch 遇到文件直链时下载二进制流，转交文档解析工具；Web Fetch 不负责文档内容解析。

执行：

```bash
rg "bytes|content-type|Content-Type|application/pdf|application/octet-stream|is_document_url|download" chat/application/web_fetch
```

重点确认：

```text
1. StaticFetcher 遇到 PDF / DOCX / XLSX 等文件直链时，返回的是什么？
2. 如果返回 bytes，FetchCoordinator 是否把它交给 ContentProcessor？
3. ContentProcessor 收到 bytes 后是否直接返回 None？
4. 文件直链是否有独立的二进制输出路径？
5. 文件直链是否会错误触发 SteelFetcher / LocalScriptFetcher fallback？
```

P0 失败条件：

```text
文件直链返回 bytes 后被 ContentProcessor 返回 None，然后 FetchCoordinator 继续浏览器 fallback。
```

这种情况会导致：

```text
PDF 直链被当成“网页抓取失败”处理；
文件二进制没有进入 document_parse；
浪费浏览器 fallback；
最终用户拿不到 file_ref / 文档解析入口。
```

本项必须人工看实际代码。它不是简单 `rg` 能完全确认的。

```text
- 每个问题给出文件路径、证据、建议修复方向

本轮不要修改代码。
```

# 19. 判定标准

## 直接 PASS

满足：

```text
1. web_fetch 没有文档解析 / OCR / force_browser / force_ocr 残留。
2. document_parse 不依赖 web_fetch。
3. PDF 完全不走 Docling / MarkItDown / 旧 DocumentParser。
4. 文件直链二进制流有明确 handoff 路径。
5. 非覆盖格式没有误进 document_parse。
6. ToolContentStore 和 URL 安全策略未变。
```

## 必须 FAIL

出现任一项：

```text
1. web_fetch 仍有 force_ocr / force_browser。
2. web_fetch 仍调用 OCR / DocumentParser。
3. PDF 仍进入 Docling。
4. document_parse 接收图片。
5. document_parse 接收 HTML / TXT / CSV / JSON / XML。
6. 文件直链 bytes 被 ContentProcessor 吞掉并触发浏览器 fallback。
7. ToolContentStore 协议被改。
8. URL 安全策略被改。
```

# 20. 最重要的三项人工检查

这三项最容易被自动搜索漏掉：

```text
1. 文件直链的二进制流最终去了哪里？
   不能在 ContentProcessor 里被当作失败，也不能进入浏览器 fallback。

2. PDF 扫描页 PP-Structure 失败时，OCR 文本是否仍然返回？
   不能因为表格失败导致整页文本丢失。

3. 工具描述是否还在误导模型？
   WebFetchTool description 不得再说自己支持 PDF / DOCX / OCR。
```

先把这轮排查跑完，再决定第二轮修复。
