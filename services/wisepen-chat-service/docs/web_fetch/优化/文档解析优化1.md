下面是一版**直接交给 Codex 的执行提示词**。它按你刚才的决策收敛：
**风格收敛 + native parser 独立成类 + Docling 按环境探测 + XLSX 走 native 主路径 + 异步化解析调用 + pathlib 化临时文件处理**。当前代码里 `DocumentParser` 仍把 Docling、legacy parser、类型识别、质量检测都放在一个类里，所以这次修改重点是把职责拆清，但不搞复杂 backend 编排器。

````text
请修改当前 document_parser.py 及其调用处，目标是完成一次中等规模重构：

核心方向：
1. DocumentParser 仍然是对外唯一入口，公开 parse / async parse_async。
2. 不做复杂 parser backend 编排器。
3. Docling 是 PDF/DOCX/PPTX 的高质量主解析器，但是否启用不靠 engine 字符串判断，而是在初始化时根据环境中是否可 import / 初始化成功来决定。
4. Native 解析器单独拆成类，负责 PDF/DOCX/XLSX/PPTX 的项目内置解析。
5. XLSX 明确走 native 主路径，不走 Docling。
6. 文档解析要支持异步调用，避免阻塞 async fetch 链路。
7. 临时文件处理全量使用 pathlib，不使用 os。
8. 质量检测只做日志，不驱动多 parser 竞赛。

────────────────────────────────────
一、风格要求
────────────────────────────────────

1. 增加 __all__，明确导出：
   __all__ = ["DocumentParser"]

2. 模块级常量和模块级辅助函数不要使用前导下划线：
   _OLE_MAGIC -> OLE_MAGIC
   _MAX_ZIP_UNCOMPRESSED_SIZE -> MAX_ZIP_UNCOMPRESSED_SIZE
   _DOCLING_DOC_TYPES -> DOCLING_DOC_TYPES
   _normalize_text -> normalize_text

3. 类内部字段继续使用下划线：
   self._min_content_length
   self._max_document_size
   self._docling_parser
   self._native_parser

4. import 顺序整理：
   - 标准库：
     asyncio
     tempfile
     pathlib.Path
     io.BytesIO
     typing
     zipfile
   - 第三方：
     pdfplumber
     docx
     openpyxl
     pptx
   - 项目内：
     settings
     logger

5. settings 不要用 getattr 兜底。
   配置项必须显式存在，不要运行时默默给默认值。

────────────────────────────────────
二、settings 调整
────────────────────────────────────

删除或不再使用：
    DOCUMENT_PARSER_ENGINE

不再用 engine 字符串控制解析器。

保留或新增：
    DOCUMENT_PARSER_ENABLE_NATIVE_FALLBACK = True

语义：
- Docling 是否可用由环境决定：能 import 且初始化成功则可用。
- 如果 Docling 不可用，启动 DocumentParser 时只记录一次日志。
- 如果 Docling 可用但单次解析异常，允许根据 DOCUMENT_PARSER_ENABLE_NATIVE_FALLBACK 决定是否回退 native。
- 不要每次 parse 都重复 import Docling，也不要每次都重复打印“Docling 未安装”。

────────────────────────────────────
三、拆出 NativeDocumentParser
────────────────────────────────────

新增类：

class NativeDocumentParser:
    def parse(self, data: bytes, doc_type: str) -> Optional[str]:
        ...

职责：
- 管理原来的 legacy/native parser。
- 包含：
  _parse_pdf
  _parse_docx
  _parse_xlsx
  _parse_pptx

命名用 native，不用 legacy。
因为 XLSX 当前就是主路径，不是“旧解析器”。

NativeDocumentParser 内部：
- PDF 使用 pdfplumber，保留 layout=True fallback：
  page.extract_text(layout=True) or page.extract_text()
- DOCX 使用 python-docx。
- XLSX 使用 openpyxl，并继续输出 Markdown + tsv fenced block：
  ## Sheet: xxx

  ```tsv
  ...
````

* PPTX 使用 python-pptx，并继续按 Slide 分组：

  ## Slide 1

注意：

* NativeDocumentParser 是内部类，不需要加入 **all**。
* 日志命名从 legacy 改为 native：
  "PDF native 文本提取"
  "DOCX native 文本提取"
  "XLSX native 文本提取"
  "PPTX native 文本提取"

────────────────────────────────────
四、拆出 DoclingDocumentParser
────────────────────────────────────

新增类：

class DoclingDocumentParser:
def **init**(self):
...
@property
def available(self) -> bool:
...
def parse(self, data: bytes, doc_type: str) -> Optional[str]:
...

职责：

* 只负责 Docling 初始化和解析。
* 只支持 doc_type in {"pdf", "docx", "pptx"}。
* 不支持 xlsx。

初始化逻辑：

* 在 **init** 中尝试 import：
  from docling.document_converter import DocumentConverter
* 如果 import 失败：

  * self._available = False
  * self._converter = None
  * log_fail("Docling 初始化", f"未能导入 Docling: {error}")
  * 只在初始化时打印一次
* 如果 DocumentConverter 初始化失败：

  * self._available = False
  * self._converter = None
  * log_fail("Docling 初始化", error)
  * 只在初始化时打印一次
* 如果成功：

  * self._available = True
  * self._converter = DocumentConverter()
  * log_ok("Docling 初始化")

parse 逻辑：

* 如果 not self.available，直接 return None，不要再打日志。
* 如果 doc_type 不支持，直接 return None。
* 使用 pathlib + TemporaryDirectory 生成临时文件。
* 不要使用 os。
* 不要使用 NamedTemporaryFile(delete=True)。

推荐写法：

with tempfile.TemporaryDirectory() as temp_dir:
temp_path = Path(temp_dir) / f"document.{doc_type}"
temp_path.write_bytes(data)

```
result = self._converter.convert(temp_path)
markdown = result.document.export_to_markdown()
```

return markdown.strip() or None

说明：

* TemporaryDirectory 退出后自动删除目录。
* Path.write_bytes 比手写 open 更简洁。
* 不需要 os.unlink。

异常处理：

* 单次 Docling 解析异常时 log_fail("Docling 文档解析", error, doc_type=doc_type)
* 返回 None。
* 这里可以每次解析失败都打日志，因为这是单次文档解析异常，不是“Docling 未安装”的重复日志。

────────────────────────────────────
五、DocumentParser 主类语义
────────────────────────────────────

DocumentParser 保持对外入口：

class DocumentParser:
def parse(self, data: bytes) -> Optional[str]:
...
async def parse_async(self, data: bytes) -> Optional[str]:
...

**init**：

* 保存：
  self._min_content_length
  self._max_document_size
  self._native_parser = NativeDocumentParser()
  self._docling_parser = DoclingDocumentParser()

parse 逻辑：

1. 文件大小检查：
   if len(data) > self._max_document_size:
   log_fail(...)
   return None

2. 文档类型识别：
   doc_type = self._detect_doc_type(data)
   if doc_type is None:
   return None

3. XLSX：

   * 直接走 native：
     text = self._native_parser.parse(data, doc_type)
     return self._finalize(text, doc_type=doc_type, parser="native") if text else None

4. PDF/DOCX/PPTX：

   * 如果 self._docling_parser.available 且 doc_type in DOCLING_DOC_TYPES：
     text = self._docling_parser.parse(data, doc_type)
     if text:
     return self._finalize(text, doc_type=doc_type, parser="docling")

     if not settings.DOCUMENT_PARSER_ENABLE_NATIVE_FALLBACK:
     return None

   * 然后走 native：
     text = self._native_parser.parse(data, doc_type)
     if text:
     return self._finalize(text, doc_type=doc_type, parser="native")

   * return None

注意：

* 不再使用 engine 变量。
* 日志字段用 parser，不用 engine。
* XLSX 不走 Docling。

parse_async：

* 使用 asyncio.to_thread 包住同步 parse：
  async def parse_async(self, data: bytes) -> Optional[str]:
  return await asyncio.to_thread(self.parse, data)

原因：

* Docling / pdfplumber / openpyxl 都是同步阻塞解析。
* aiofiles/aiofile 对这里收益有限，因为瓶颈不是简单文件读写，而是解析过程。
* 第一版不要引入 aiofiles / aiofile 新依赖。
* 异步化应该先用 asyncio.to_thread，最稳。

────────────────────────────────────
六、ContentProcessor 调用处异步化
────────────────────────────────────

如果当前 ContentProcessor.process 是同步函数，可以先保持不动。

但 FetchCoordinator 在处理 bytes 文档时，不要直接在事件循环里同步解析大文档。

请增加异步入口：

ContentProcessor:
async def process_async(self, content: str | bytes) -> Optional[str]:
if isinstance(content, bytes):
return await self._document_parser.parse_async(content)
return self._process_text(content)

保留原同步 process，兼容其他调用：
def process(self, content: str | bytes) -> Optional[str]:
if isinstance(content, bytes):
return self._document_parser.parse(content)
return self._process_text(content)

然后 FetchCoordinator 中 raw 内容处理优先调用：
result = await self._processor.process_async(content)

不要在 FetchCoordinator 里直接 asyncio.to_thread(self._processor.process, content)，因为文档解析器自己已经有 parse_async。

────────────────────────────────────
七、质量检测日志
────────────────────────────────────

保留当前质量检测：

* longest_token > 120

但日志字段增强：

longest_token = ...

log_fail(

* 不因为质量检测失败而切换 parser。
* 不做多个 parser 质量竞赛。

────────────────────────────────────
十一、验收标准
────────────────────────────────────

1. 未安装 Docling 时：

   * DocumentParser 初始化时只打印一次 Docling 初始化失败日志。
   * PDF/DOCX/PPTX 能通过 native fallback 继续解析。
   * 不会每次 parse 都重复打印 import 失败。

2. 安装 Docling 时：

   * PDF/DOCX/PPTX 优先走 Docling。
   * 日志包含 parser=docling。
   * XLSX 仍走 native。
   * 日志包含 parser=native。

3. Docling 单次解析失败时：

   * 如果 settings.DOCUMENT_PARSER_ENABLE_NATIVE_FALLBACK=True，则走 native。
   * 如果 False，则返回 None。
   * 不影响其他文档解析。

4. async 路径：

   * ContentProcessor.process_async(bytes) 使用 DocumentParser.parse_async。
   * FetchCoordinator raw 内容处理使用 await self._processor.process_async(content)。
   * 大 PDF 解析不会直接阻塞 event loop 主路径。

5. 风格：

   * **all** = ["DocumentParser"]
   * 模块级常量和辅助函数无前导下划线。
   * 类内部字段仍使用下划线。
   * 临时文件处理使用 pathlib.Path，不使用 os。

```

我再补一句判断：这里**不建议引入 aiofile/aiofiles**。文档解析耗时主要在 Docling/pdfplumber/openpyxl 解析过程，不是 Python 异步文件读写；`asyncio.to_thread` 把整个同步解析移出事件循环，收益更直接，依赖也更少。
```
