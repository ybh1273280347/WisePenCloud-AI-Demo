对，这个文件最直观的问题就是**日志重复 + 成功/失败处理分散**。另外我看到一个更严重的问题：当前 `_cache` 用的是普通 `dict`，但后面调用了 `move_to_end()` 和 `popitem(last=False)`，这会直接运行时报错。

# 必须先修的 bug

现在：

```python
self._cache: Dict[Tuple[str, bool], Tuple[float, str]] = {}
```

但后面：

```python
self._cache.move_to_end(key)
self._cache.popitem(last=False)
```

普通 `dict` 没有 `move_to_end`，`dict.popitem()` 也不支持 `last=False`。这里要么改回：

```python
from collections import OrderedDict

self._cache: OrderedDict[Tuple[str, bool], Tuple[float, str]] = OrderedDict()
```

要么更推荐：直接用 `cachetools.TTLCache`。既然你项目已经为 `ToolContentStore` 引入了 `cachetools`，这里也可以统一掉手写 TTL/LRU。

# 推荐优化方向

## 1. 提取日志 helper

现在同类日志重复了很多次：

```python
log_fail("网页抓取", ..., url=url, fetcher=fetcher_name)
log_ok("网页抓取", url=url, fetcher=fetcher_name, length=len(...))
failure_reasons.append(...)
```

建议提取模块级函数：

```python
def log_fetch_fail(
    reason: str,
    *,
    url: str,
    fetcher: str,
    failure_reasons: List[str],
    detail: str,
) -> None:
    failure_reasons.append(f"{fetcher}: {detail}")
    log_fail("网页抓取", reason, url=url, fetcher=fetcher)


def log_fetch_success(
    *,
    url: str,
    fetcher: str,
    length: int,
) -> None:
    log_ok("网页抓取", url=url, fetcher=fetcher, length=length)
```

这样主循环会清楚很多。

---

## 2. 提取内容处理分支

现在 `fetch()` 里既做调度，又做：

```text
markdown 内容长度判断
raw 内容 processor 处理
缓存写入
成功日志
失败日志
```

可以提取两个实例方法，因为它们使用了类内阈值和 processor：

```python
async def _handle_markdown_content(...)
async def _handle_raw_content(...)
```

不过如果你想让 `fetch()` 一眼看到主逻辑，也可以只抽 `_accept_markdown()` 和 `_process_raw()`。

推荐：

```python
def _accept_markdown(
    self,
    content: str,
    *,
    min_length: int,
    url: str,
    fetcher_name: str,
    failure_reasons: List[str],
) -> Optional[str]:
    ...
```

```python
async def _process_raw(
    self,
    content: str | bytes,
    *,
    url: str,
    fetcher_name: str,
    failure_reasons: List[str],
) -> Optional[str]:
    ...
```

主循环可以变成：

```python
if content_type == "markdown":
    result = self._accept_markdown(...)
else:
    result = await self._process_raw(...)

if result is None:
    continue

self._log_success(...)
self._set_cached(...)
return result
```

## 3. 缓存建议改用 `TTLCache`

既然你已经接受 `cachetools`，这里没必要继续手写：

```python
created_at
age
cache_max_items
move_to_end
popitem
```

建议：

```python
from cachetools import TTLCache
```

然后：

```python
self._cache: TTLCache[Tuple[str, bool], str] = TTLCache(
    maxsize=cache_max_items,
    ttl=cache_ttl_seconds,
)
```

`_get_cached`：

```python
def _get_cached(self, url: str, force_browser: bool) -> Optional[str]:
    self._cache.expire()
    return self._cache.get((url, force_browser))
```

`_set_cached`：

```python
def _set_cached(self, url: str, force_browser: bool, markdown: str) -> None:
    self._cache.expire()
    self._cache[(url, force_browser)] = markdown
```

这样 `_cache_ttl_seconds` 和 `_cache_max_items` 也不需要保存成实例字段，除非你要日志里输出。

# 最终判断

这里不只是“日志可以提取”，还有一个实际 bug：

我建议这次直接用 `TTLCache` 修掉，同时顺手提取日志 helper。这样 `FetchCoordinator.fetch()` 会短很多，也更容易看出真正的降级链。
