在已有清理任务基础上，追加执行以下排查。

1. 真重复识别：
   - 只有语义一致、失败策略一致、未来修改必须同步的重复才抽取。
   - 模式相似但失败策略不同的代码不要抽。
   - 一两行重复不要抽，除非是项目级协议。

2. 长函数处理：
   - 超过 30 行不等于必须拆。
   - pipeline、降级链、安全校验链、异常分类、magic bytes 检测、反爬规则检测可以合理较长。
   - 只有职责混杂、嵌套过深、重复构造明显时才拆。

3. helper 清理：
   - 调用 0 次的 wrapper 删除。
   - 调用 1 次且 1～2 行的 helper 内联。
   - 调用 3 次以上或统一协议/日志/安全语义的 helper 保留。
   - 不使用 self 的 helper 不放类里。

4. 日志：
   - 只中文化开发者日志和内部异常。
   - 不翻译 Tool Result / Tool Error / ToolContent Metadata / schema / 模型可见 Markdown / worker JSON 字段。
   - stage 使用稳定中文短语。
   - 不重复打印同一初始化日志。

5. 异常：
   - UrlSecurityError 必须终止降级链。
   - OcrProcessingError 只表示 OCR 处理失败。
   - 不要用 None 表示安全拒绝。
   - 不要把安全错误吞成普通抓取失败。

6. 安全：
   - 所有 URL 下载入口必须 validate_public_http_url。
   - 不允许 follow_redirects=True。
   - redirect 每跳重新校验。
   - 不放宽端口、localhost、.local、userinfo、DNS 解析策略。

7. 配置：
   - 不使用 getattr(settings, "...", default)。
   - 不在业务代码里静默 clamp settings。
   - 不改变 settings.FIELD_NAME 访问方式。
   - 不新增 nested settings。

8. DI：
   - 不使用 Optional 依赖兜底创建复杂对象。
   - 涉及网络、worker、subprocess、cache、storage、browser、OCR、RPC 的对象由 container 或明确工厂装配。
   - 纯函数不注册进 container。

9. import 副作用：
   - 主服务 import 阶段不 import paddleocr。
   - PyMuPDF lazy import。
   - Docling lazy singleton。
   - 删除未使用 import，但不处理 test 目录。

10. 生命周期：
   - 有 worker/task/client 的对象必须有 close/stop。
   - close 可重复调用。
   - close 实际接入应用 shutdown。
   - 不留下 pending task。

11. 长内容：
   - 不允许手写内容截断。
   - 长内容统一 ToolContentStore。
   - 搜索结果 max_results 截断不要误判为内容截断。

12. 输出：
   - 先报告，不直接改。
   - P0：真实风险，例如安全语义、重复常量、死 wrapper、错误生命周期。
   - P1：明显维护性问题，例如重复 helper、英文开发日志。
   - P2：可暂缓，例如合理较长函数、模式相似但不值得抽象。
