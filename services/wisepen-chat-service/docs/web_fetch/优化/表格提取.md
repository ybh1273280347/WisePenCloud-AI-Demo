## 结论

`spreadsheet/parser.py` 当前主路径是对的：用 `pandas.read_excel(..., sheet_name=None)` 一次读取所有 sheet，然后把每个 sheet 同时写入 `text` 和 `tables`。pandas 官方文档确认，`sheet_name=None` 会返回包含所有 sheet 的 `DataFrame` 字典；`dtype=object` 可以保留 Excel 中存储的数据，避免 pandas 自动推断类型。([Pandas][1])

但当前文件有几处明显需要小修：

```text
我确定要改：
1. typing 改成项目风格：List / Dict / Any，不用 list[str]。
2. 删除 CSV 校验，CSV 不会路由进 SpreadsheetParser。
3. 抽内部常量。
4. table_id 改成 1-based。
5. 补 public class docstring。
6. pandas 读取和 TSV 输出的细节稍微整理，提高可读性。

需要人工确认后再小修：

## 第三方库 API 确认

`pd.read_excel(path, sheet_name=None, dtype=object)` 这个方向正确。pandas 官方说明：`sheet_name=None` 会读取所有工作表并返回字典；`dtype=object` 会保留 Excel 中存储的数据，而不是自动推断列类型。([Pandas][1])

pandas 也说明 `read_excel` 支持 `.xls/.xlsx/.ods` 等文件格式，并且 `engine=None` 时会根据文件类型选择引擎；这和当前 `SpreadsheetParser` 处理 `XLSX / XLS / ODS` 的定位一致。([Pandas][1])

## 建议当前文件改成这样

````python
from pathlib import Path
from typing import Any, Dict, List

from chat.application.document_parse.models import DocumentParseResult, ParsedPage, ParsedTable
from chat.application.document_parse.text_utils import normalize_text


_FILE_TYPE_SPREADSHEET = "spreadsheet"
_PAGE_TYPE_SPREADSHEET = "spreadsheet"
_PARSER_NAME = "SpreadsheetParser"
_BACKEND_PANDAS = "pandas"
_TSV_FENCE = "tsv"


class SpreadsheetParser:
    """电子表格文档解析器。"""

    def parse(self, path: Path) -> DocumentParseResult:
        import pandas as pd

        sheets = pd.read_excel(path, sheet_name=None, dtype=object)

        text_parts: List[str] = []
        tables: List[ParsedTable] = []
        sheets_info: List[Dict[str, Any]] = []

        for sheet_name, df in sheets.items():
            rows = self._rows_from_dataframe(df)
            sheet_name_text = str(sheet_name)
            sheet_number = len(tables) + 1

            table = ParsedTable(
                table_id=f"sheet_{sheet_number}",
                source=_BACKEND_PANDAS,
                rows=rows,
                page_index=None,
                metadata={
                    "sheet_name": sheet_name_text,
                    "rows": len(df),
                    "columns": len(df.columns),
                },
            )
            tables.append(table)

            sheets_info.append(
                {
                    "name": sheet_name_text,
                    "rows": len(df),
                    "columns": len(df.columns),
                }
            )

            text_parts.append(f"## Sheet: {sheet_name_text}")
            text_parts.append("")
            text_parts.append(f"```{_TSV_FENCE}")
            text_parts.extend(["\t".join(row) for row in rows])
            text_parts.append("```")
            text_parts.append("")

        text = normalize_text("\n".join(text_parts))

        page = ParsedPage(
            page_index=0,
            text=text,
            page_type=_PAGE_TYPE_SPREADSHEET,
            tables=tables,
            metadata={"parser": _BACKEND_PANDAS},
        )

        return DocumentParseResult(
            text=text,
            source=str(path),
            file_type=_FILE_TYPE_SPREADSHEET,
            pages=[page],
            tables=tables,
            metadata={
                "parser": _PARSER_NAME,
                "spreadsheet_backend": _BACKEND_PANDAS,
                "sheet_count": len(sheets),
                "sheets": sheets_info,
                "page_count": 1,
                "table_count": len(tables),
            },
            warnings=[],
        )

    def _rows_from_dataframe(self, df: Any) -> List[List[str]]:
        filled = df.fillna("")
        rows: List[List[str]] = [[str(col) for col in filled.columns.tolist()]]
        rows.extend(filled.astype(str).values.tolist())
        return rows
````

## 需要人工确认后再小修的点

### 1. 是否使用 `keep_default_na=False`

现在代码是：

```python
pd.read_excel(path, sheet_name=None, dtype=object)
```

随后：

```python
df.fillna("")
```

这会把 pandas 识别为 NA 的值变成空字符串。若用户 Excel 里真的有字符串 `"NA"`、`"N/A"` 等，pandas 默认可能把它们识别为缺失值。若你希望最大程度保留单元格原文，可以考虑：

```python
pd.read_excel(path, sheet_name=None, dtype=object, keep_default_na=False)
```

pandas 文档中 `dtype=object` 是保留存储数据类型的做法，但缺失值解析仍由 NA 相关参数控制；是否关闭默认 NA 识别要看你们希望“保真”还是“清洗后更规整”。([Pandas][1])

我的建议：**文档解析更偏保真，倾向加 `keep_default_na=False`**。但这会影响现有测试里对空单元格 / NA 字符串的预期，建议确认后小修。

---

### 2. 是否限制大表输出

当前会把所有 sheet 的所有行全部写入 `result.text`。这可能非常大，不过后续 `ToolContentStore` 会分块缓存。但如果 Excel 超大，解析和拼接本身会有成本。

当前不建议在 parser 里截断，因为这会让 `tables` 和 `text` 不完整。后续若有性能问题，应该设计明确的：

```text
max_rows_per_sheet
max_columns_per_sheet
truncated metadata
```

现在不加隐式截断。

---

### 1. 不建议在这里处理 CSV

CSV 已经明确不属于 `document_parse`。不要让 `SpreadsheetParser` 出现 CSV 分支。

### 2. 不建议手动指定 pandas engine

pandas 会根据后缀选择引擎；目前支持 `.xlsx/.xls/.ods`，让 pandas 默认处理更简单。除非实测某个格式引擎选择错误，再加显式配置。

### 3. 不建议在这里捕获 pandas 异常

读取失败应该冒泡到 `DocumentParseTool` / service 层，返回 Tool Error。这里不要吞掉异常。
