# 2. P1-1：工具描述语义清理

## 2.1 WebFetchTool description

`web_fetch` 的描述必须只表达：

```text
- 抓取网页 URL
- 对 HTML 页面提取正文
- 文件直链只做 handoff
- 不解析文档内容
```

必须删除这些语义：

```text
- supports PDF
- supports DOCX
- supports XLSX
- supports PPTX
- scanned PDF
- OCR
- force_ocr
- force_browser
- document parsing
- parses direct document links
```

推荐描述：

```python
TOOL_DESCRIPTION = (
    "Fetches a web URL and extracts readable Markdown from HTML pages. "
    "For direct file links, this tool only performs binary/file handoff; "
    "document content parsing belongs to document_parse."
)
```

---

## 2.2 DocumentParseTool description

`document_parse` 的描述必须明确：

支持：

```text
PDF
DOCX
PPTX
EPUB
XLSX / XLS / ODS
```

不支持：

```text
HTML
TXT
MD
CSV
JSON
XML
images
audio
video
URL fetching
```

推荐描述：

```python
TOOL_DESCRIPTION = (
    "Parses binary document files into Markdown text and structured tables. "
    "Supports PDF, DOCX, PPTX, EPUB, XLSX, XLS, and ODS. "
    "Does not fetch URLs. Does not handle HTML, TXT, MD, CSV, JSON, XML, images, audio, or video."
)
```

---

## 2.3 错误提示语义统一

不支持格式时，不要写模糊错误。

推荐格式：

```text
[Tool Error] Unsupported document type: .html. HTML pages should be handled by web_fetch.
```

```text
[Tool Error] Unsupported document type: .json. JSON should be read directly by the caller, not document_parse.
```

```text
[Tool Error] Unsupported document type: .png. Images should be handled by the multimodal model, not document_parse.
```

# 4. P1-3：metadata / warnings 语义补齐

## 4.1 通用 metadata

所有 `document_parse` 结果 metadata 至少包含：

```python
{
    "tool": "document_parse",
    "file_type": "...",
    "parser": "...",
    "source": "...",
    "page_count": ...,
    "table_count": ...,
    "warnings": [...],
}
```

不要出现：

```python
{
    "tool": "web_fetch",
    "force_ocr": ...,
    "auto_ocr": ...,
}
```

---

## 4.2 PDF metadata

PDF 必须包含：

```python
{
    "parser": "PdfParser",
    "pdf_backend": "pymupdf",
    "ocr_backend": "paddleocr",
    "table_backends": ["camelot", "pp_structure"],
    "page_type_counts": {
        "text": 0,
        "mixed": 0,
        "scanned": 0,
        "empty": 0,
    },
}
```

每页 metadata 建议包含：

```python
{
    "page_type": "text|mixed|scanned|empty",
    "ocr_used": True | False,
    "text_backend": "pymupdf|paddleocr|none",
    "table_backend": "camelot|pp_structure|none",
}
```

---

## 4.3 Office metadata

Office 必须包含：

```python
{
    "parser": "OfficeParser",
    "selected_parser": "docling|markitdown|python_fallback",
    "fallback_chain": ["docling", "markitdown", "python_fallback"],
}
```

---

## 4.4 Spreadsheet metadata

表格文件必须包含：

```python
{
    "parser": "pandas",
    "sheet_count": 3,
    "sheets": [
        {
            "name": "Sheet1",
            "rows": 100,
            "columns": 8,
        }
    ],
}
```

---

## 4.5 warning 统一格式

统一 warning 字符串，不要散乱写法。

推荐：

```text
page_parse_failed: page=3: ValueError: ...
table_parse_failed: page=2: RuntimeError: ...
ocr_failed: page=5: TimeoutError: ...
docling_failed: RuntimeError: ...
markitdown_failed: ValueError: ...
python_fallback_used: reason=markitdown_failed
```

重点：

```text
PP-Structure 失败必须是 table_parse_failed。
PP-Structure 失败不能吞掉 OCR 文本。
Docling 失败不能直接叫 parse_failed，要叫 docling_failed。
MarkItDown 失败不能直接叫 fallback_failed，要叫 markitdown_failed。
```

# 5. P1-4：配置命名语义清理

## 5.1 背景

第一轮后，OCR 能力已经属于 `document_parse` 的 PDF 扫描页路径，不再属于 `web_fetch`。

因此配置名中不应该再出现：

```text
WEB_FETCH_OCR
WEB_FETCH_PDF
WEB_FETCH_DOCUMENT
```

---

## 5.2 推荐配置命名

旧：

```text

WEB_FETCH_OCR_RENDER_DPI
WEB_FETCH_OCR_MAX_IMAGE_PIXELS
WEB_FETCH_OCR_MAX_PAGES
```

新：

```text
OCR_TIMEOUT
OCR_RENDER_DPI
OCR_MAX_IMAGE_PIXELS
PDF_OCR_MAX_PAGES
PDF_RENDER_DPI
```

如果担心环境变量兼容，可以短期兼容读取旧名，但新代码、新文档、新测试只使用新名。

---

## 5.3 搜索命令

```bash
rg "WEB_FETCH.*OCR|WEB_FETCH.*PDF|WEB_FETCH.*DOCUMENT" chat tests docs
```

处理规则：

```text
document_parse 中不得出现 WEB_FETCH_OCR。
web_fetch 中不得出现 OCR 配置。
docs 中不得推荐 WEB_FETCH_OCR。
```

# 8. P2-1：代码风格清理

## 8.1 删除 `__all__`

全局执行：

```bash
rg "__all__" chat
```

删除所有 `__all__`。

不新增替代导出列表。

---

## 8.2 内部 helper 下划线化

规则：

```text
模块外要用的，保持 public。
模块内自用的，加 `_`。
```

内部 helper 包括：

```text
检测函数
格式化函数
内部常量
内部 dataclass
内部异常
内部转换函数
日志 helper
```

---

## 8.3 禁止跨模块 import 私有符号

执行：

```bash
rg "from .* import _|import .*._" chat
```

原则：

```text
业务代码不 import 私有符号。
如果需要跨模块复用，说明它应该成为 public helper 或移动到公共模块。
```

---

## 8.4 不借风格任务做业务重构

风格清理只能做：

```text
重命名
同步引用
删除 __all__
删除无意义导出
```

不能做：

```text
拆模块
改返回格式
改协议
改 parser 流程
改 tool schema
```
